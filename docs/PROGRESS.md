## Key decisions & conventions
- Names: Worker tradesense, D1 tradesense-db, R2 tradesense-files, brand TradeSense.
- IDs: TEXT ULID via newId(). Timestamps: ISO-8601 UTC TEXT via nowIso(). Dates: YYYY-MM-DD TEXT (UTC calendar day). Booleans: INTEGER 0/1.
- Row shapes camelCase in repository interfaces; snake_case only inside repositories/d1. Only repositories/d1 touches D1Database. D1 allows 100 bound values per statement: batch lookups by id are capped at 90 ids.
- Error format: { error: { code, message, details? } }. AppError helpers (badRequest, unauthorized, forbidden, notFound, conflict, tooMany); locked edits use AppError(409, "locked", msg, { fields }); upload errors 413 too_large, 415 unsupported_type.
- Hono 4.6.14 (own ErrorStatus type in errors.ts). Aliases @shared/*, @client/*.
- Auth/CSRF as Phase 1 (cookie ts_session, header x-csrf-token; apiForm adds it for multipart).
- Staff pages: every /api/admin/* route needs admin:access; finer permission per route. Permission map NOT changed in Phases 3 or 4. Phase 4 permission use: event:manage (admin Events screen), post:publish (Engagement counts), user:manage (Engagement "who viewed").
- Settings, posts, notes, attachments, locks, roles, catalog rules, editor behaviour: unchanged (posts dated by Monday for weekly, publish completeness rules, locked fields after publish with post_revisions in the same batch, analyst own-drafts only).
- Repositories types: types.base.ts holds the Phase 2 interfaces; types.ts re-exports it and declares extended interfaces with the SAME names. listAugment.ts (lists), publicTypes.ts (events, bookmarks, viewLog, subscriptions) and publicListTypes.ts (publicLists) attach members to Repositories by declaration merging. TODO: when types.ts is next edited for another reason, fold types.base, listAugment, publicTypes and publicListTypes into one file.
- Results: one result per post, never UPDATE/DELETE (trigger); service checks published + valid_until passed + no result; evaluation_rule_version set by the server; corrections append-only; effective outcome = latest correction else original. The SQL EFFECTIVE expression (EFF) now lives in THREE places and must stay identical: d1/results.ts, d1/lists.ts, d1/publicLists.ts.
- Evaluation rules append-only; version = max + 1 with UNIQUE(version).
- Users: admins cannot change their own role; seed system user cannot be changed; staff accounts need a password; role change, password reset and 2FA reset delete the user's sessions. No user delete or disable yet.
- Plans never deleted (deactivate); codes immutable; region prices used only when settings.regional_pricing_enabled is true.
- Saved views: personal, NOT audited; filters = flat string map identical to the list's URL query.
- List engine (admin): filters are bound parameters, sorts from allow-lists, `mine=1` mapped to createdBy in the service. Bulk max 100 rows/request; CSV cap 5000 rows.
- ACCESS RULES (Phase 4, services/access.ts, numbers come from settings): entitled = staff OR a subscription with status active and starts_at <= now < expires_at (a signed-in member without one is treated like a visitor). Entitled sees every published item. Everyone else: an item is open if its content date is <= today - open_archive_days (open_archive_days = 0 switches the open archive OFF), else a FREE item is open once published_at <= now - free_delay_hours (0 = at once), else locked (paid) or delayed (free, inside the delay). Content date = post_date for daily, week_start_date + 6 days for weekly, note_date for notes. visibilityFor()/isOpen()/evaluateAccess() are the single implementation; the public list SQL mirrors isOpen (openPost/openNote in d1/publicLists.ts, weekly handled without SQL date functions).
- NON-LEAK RULES: (1) PublicService turns rows into DTOs and sets `content = null` unless the item is open; locked items carry only market, dates, access, lock info. (2) Content filters (bias, confidence, sentiment, result, tag, note status, screenshot, keyword) are ANDed with the viewer's open condition in SQL, so locked rows never match; public sorts are limited to date, published, market (+ killzone for notes). (3) Detail endpoints answer 200 with detail = null and editHistory = [] while locked. (4) Draft/scheduled items are never public: status = 'published' is hard-coded in the public SQL and detail services.
- Screenshots: attachment access inherit = its owner's access; public = always (owner published); free/paid go through AccessService. The rule exists in TWO places that must stay in sync: AttachmentService.canView (guards /files/:id) and PublicDetailService.attachmentItem (decides whether a url is handed out). Result screenshots follow their post.
- Watermark: user ULID encoded as 5 bits per character in zero-width characters (U+200B/U+200C between U+2060 markers), appended to up to 12 paragraphs of body/note text (fewer for other fields), code fences skipped; plus a visible footer token (first 10 hex of sha256("wm:" + IP_HASH_SALT + ":" + userId + ":" + entityId), upper case). Applied to every signed-in viewer incl. staff; none for visitors. decodeWatermarks() in lib/watermark.ts recovers the id from pasted text (no admin tool for it yet). Changing IP_HASH_SALT changes footer tokens and IP hashes.
- View log: only OPEN detail views of published posts/notes are logged (/files views are not; entity type "attachment" is reserved); staff views are skipped; same viewer (user id, or ip hash for visitors) within 10 minutes counts once; ip_hash = first 32 hex of sha256(salt + ":" + ip); logging never throws.
- Bookmarks: PUT/DELETE /api/public/bookmarks/:type/:id (login needed; only published items); the list is GET /api/public/feed?bookmarked=1 (header link "Bookmarks" = /feed?bookmarked=1).
- Public edit history: from post_revisions, only field LABELS (shared/editHistory.ts) and time, never old/new text or editor; the route adds `editHistory` next to the detail DTO.
- Public events: table `events`, source "manual" (admin Events screen), times UTC, public default window = next 30 days. Public rules: all versions, newest first, active flagged.
- Killzone windows (informational only) are in shared/killzones.ts in New York time; the spec did not define hours, edit that file to change them. Matrix shows them in the viewer's timezone (client lib/tz.ts; choice remembered in localStorage key ts_tz, else account timezone, else browser).
- Public client conventions: all public queries use usePublicQuery (key includes the viewer id, so login/logout never shows stale data; invalidate ["public"] after bookmark changes). The drawer state is the URL param ?open=post:ID|note:ID (useDrawer); put <DetailDrawer /> on any page that opens items. Cards (ItemCards.tsx) are ONE <button> with inline elements only. Bias/outcome/status/impact are always icon + word. LockPlaceholder (PublicBits.tsx) is the ONE place to add the pricing call to action in Phase 5.
- Heatmap shows daily posts of ONE market per month; Weekly outlook = feed with type=weekly and a one-date range (weekly posts are dated by their Monday); Today's feed period "today" excludes weekly posts.
- Audit actions added in Phase 4: event.create|update|delete, engagement.viewers (opening the viewer list exposes member emails, so it is audited).
- HOW TO ADD A NEW ENDPOINT: (1) Zod schema in src/shared/ + DTO type; (2) repository interface + D1 implementation + register in d1/index.ts; (3) service in src/server/services/ (business and lock rules, Actor = {id, role}); (4) route file in src/server/routes/ with requirePermission("x:y"), parseJson / parseQuery, and audit(c, action, entity, id, diff) after every admin change; (5) mount in src/server/index.ts (static paths before /:id).
- HOW TO ADD A NEW ADMIN SCREEN: page in src/client/pages/admin/, nav item in components/admin/nav.ts, <Route> in pages/Admin.tsx wrapped in <RequirePermission>, data via TanStack Query + api(), shared look from components/ui.tsx.
- HOW TO ADD A PUBLIC PAGE: page in src/client/pages/, <Route> in App.tsx, link in components/publicNav.ts; fetch with usePublicQuery; build items from PublicService (never send content for a locked item).
- HOW TO ADD A PUBLIC FILTER: add it to publicFeedQuery (shared/public.ts), map it in PublicService.feed, add the WHERE clause in postWhere/noteWhere (d1/publicLists.ts) as a METADATA filter or, if it reveals content, in the `content` group, add it to PublicPostFilter/PublicNoteFilter if new, add the control in components/public/FeedFilters.tsx (FEED_KEYS).
- HOW TO ADD A COLUMN TO AN ADMIN LIST: add the field to the row DTO (shared/lists.ts) and the SELECT/mapper in repositories/d1/lists.ts; add a ColumnDef in shared/lists.ts; add its cell in the page's `cell` map and its value in the CSV map in services/lists.ts (same id).
- HOW TO ADD A FILTER TO AN ADMIN LIST: add it to postFilterShape/noteFilterShape (shared/lists.ts), to PostFilterBase/NoteFilterBase (listTypes.ts), map it in postFilterFromQuery/noteFilterFromQuery (services/lists.ts), add the WHERE clause in postWhere/noteWhere (d1/lists.ts), add the control on the page.
- Windows Git Bash has no python: deliver every file as a full heredoc script, never python/sed edits.
